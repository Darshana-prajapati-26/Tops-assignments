💬 Stack Trace Explanation (Q13 & Q14)

A stack trace shows the exact sequence of function calls that led to an error. It is read bottom-up — the bottom line is where execution started and the top line is where the error actually happened.

In the example above: the user clicked a button → triggerError() was called → it called validateProduct() → which called JSON.parse() on invalid data → JSON.parse threw a SyntaxError. Each line in the trace includes the file name, line number, and column number, pinpointing exactly where the error occurred.

📝 Summary in Own Words (Q15)

The stack trace is like a breadcrumb trail of function calls. When an error occurs, JavaScript records every function that was active at that moment, most recent first. The first line tells you what went wrong (e.g., SyntaxError), and the lines below show how the code got there step by step. The line number next to each function name takes you directly to the problematic code in your file, making it much faster to find and fix bugs.
